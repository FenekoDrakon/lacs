# lacs
---

# 1. Философия языка

LACS — универсальный статически типизированный компилируемый язык программирования с:

- проверкой типов на этапе компиляции;
- явными типами переменных;
- отдельным динамическим типом `let`, предоставляемым встроенной стандартной библиотекой `std.let`;
- изменяемыми и неизменяемыми контейнерами;
- функциями первого класса и замыканиями;
- generic-функциями и generic-контейнерами;
- предсказуемым порядком вычисления выражений;
- явной семантикой копирования, ссылок и владения;
- блоковой областью видимости;
- безопасным ядром без произвольных raw pointers;
- FFI для взаимодействия с внешним нативным кодом;
- стандартной библиотекой общего назначения.

Язык не навязывает объектно-ориентированный, процедурный или функциональный стиль. Все три стиля должны быть реализуемы средствами ядра и стандартной библиотеки.

Основная модель исполнения LACS — **AOT-компиляция в нативный код**. Рекомендуемая архитектура компилятора:

```text
.lac
 ↓
Lexer
 ↓
Parser
 ↓
AST
 ↓
Semantic analysis / type checking
 ↓
LACS IR
 ↓
LLVM IR
 ↓
LLVM optimization
 ↓
Native machine code
 ↓
Executable
```

# 2. Программа и исходные файлы

## 2.1. Исходный файл

Исходные файлы LACS имеют расширение `.lac`.

Один файл является одним модулем.

Файл может содержать:

- объявления типов;
- объявления констант;
- глобальные переменные;
- определения функций;
- импорты модулей;
- экспорты символов.

Пример:

```lacs
import std.math

const float PI2 = std.math.pi * 2

fn main() {
    println(PI2)
}
```

## 2.2. Точка входа

Исполняемая программа должна содержать ровно одну функцию:

```lacs
fn main() {
    ...
}
```

`main()` не принимает аргументов.

Возвращаемый тип `main` обязан быть `None`. Отсутствие `return` эквивалентно `return None`.

## 2.3. Порядок объявлений

Порядок функций, типов и констант верхнего уровня внутри одного модуля не влияет на возможность обращения к ним. Символы верхнего уровня разрешаются после разбора модуля.

# 3. Лексика

## 3.1. Идентификаторы

Идентификатор:

- начинается с латинской буквы или `_`;
- затем может содержать латинские буквы, цифры и `_`;
- чувствителен к регистру.

Примеры:

```text

my_var
ScanMode1
_temp
```

`x` и `X` — разные идентификаторы.

## 3.2. Ключевые слова

Минимальный набор ключевых слов ядра:

```text

return
if
elif
else
loop
while
for
in
break
continue
struct
enum
match
export
import
from
as
extern
unsafe
true

None
```

`let` **не является ключевым словом ядра**. Имя `let` предоставляется библиотекой `std.let`.

Границы блоков задаются `{` и `}`.

Отступы не являются частью грамматики. Рекомендуемый стиль форматирования — 4 пробела.


Многострочный комментарий:

```lacs

   комментарий
   на нескольких строках
*/
```

# 4. Базовые типы

LACS содержит следующие фундаментальные числовые и логические типы:

| Тип | Описание |
|---|---|
| `int8` | Знаковое целое 8 бит |
| `int16` | Знаковое целое 16 бит |
| `int32` | Знаковое целое 32 бит |
| `int64` | Знаковое целое 64 бит |
| `float16` | IEEE 754 binary16 |
| `float32` | IEEE 754 binary32 |
| `float64` | IEEE 754 binary64 |
| `bool` | `true` или `false` |
| `text` | Неизменяемая Unicode-строка |
| `complex` | Комплексное число с компонентами `float64` |
| `None` | Единственное значение отсутствия значения |

Беззнаковые целочисленные типы (`uint8`, `uint16`, `uint32`, `uint64`) в ядро LACS не входят. При необходимости они могут появиться позже в стандартной или специализированной библиотеке.

## 4.1. Псевдонимы

```text
int   == int64
float == float64
```

Поэтому:

```lacs
int x = 10
float y = 3.14
```

означает `int64` и `float64` соответственно.

`float16`, `float32`, `int8`, `int16`, `int32` и `int64` доступны явно.

## 4.2. Диапазоны и переполнение

Все целочисленные типы имеют фиксированный диапазон.

Переполнение целого типа является ошибкой выполнения.

Реализация не имеет права превращать переполнение в неопределённое поведение или молча менять тип значения.

## 4.3. Floating point

`float16`, `float32` и `float64` следуют модели IEEE 754 и могут содержать `NaN`, `+Inf` и `-Inf`.

Для всех floating-point типов действуют правила IEEE 754, в частности:

- `NaN == NaN` → `false`;
- `NaN != NaN` → `true`;
- сравнения порядка с `NaN` (`<`, `>`, `<=`, `>=`) дают `false`.

## 4.4. Complex

`complex` содержит действительную и мнимую части типа `float64`.

Пример:

```lacs
complex z = 1 + 2i
```

Поддерживаются:

```text
+
-
*
/
==
!=
```

Операторы порядка:

```text
<
>
<=
>=
```

для `complex` запрещены.

# 5. Числовое продвижение и приведение

## 5.1. Иерархия числовых типов

При смешанных числовых выражениях используется общая иерархия:

```text
int8 < int16 < int32 < int64 < float16 < float32 < float64 < complex
```

Правило означает:

1. сначала учитывается разрядность;
2. тип с большей разрядностью считается более мощным независимо от класса (`int` или `float`);
3. при одинаковой разрядности `float` сильнее `int`;
4. `complex` сильнее всех обычных числовых типов.

Примеры:

```text
int8   + int16    -> int16
int16  + int32    -> int32
int64  + float32  -> float64
int16  + float32  -> float32
float16 + int64   -> float64
float32 + float64 -> float64
float64 + int32   -> float64
complex + float64 -> complex
complex + int64   -> complex
```

Таким образом, например:

```text
int64 + float32 = float64
```

Полная таблица результата для `+`, `-` и `*` при отсутствии специального правила операции:

| `+` / `-` / `*` | `int8` | `int16` | `int32` | `int64` | `float16` | `float32` | `float64` | `complex` |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `int8` | `int8` | `int16` | `int32` | `int64` | `float16` | `float32` | `float64` | `complex` |
| `int16` | `int16` | `int16` | `int32` | `int64` | `float16` | `float32` | `float64` | `complex` |
| `int32` | `int32` | `int32` | `int32` | `int64` | `float16` | `float32` | `float64` | `complex` |
| `int64` | `int64` | `int64` | `int64` | `int64` | `float64` | `float64` | `float64` | `complex` |
| `float16` | `float16` | `float16` | `float16` | `float64` | `float16` | `float32` | `float64` | `complex` |
| `float32` | `float32` | `float32` | `float32` | `float64` | `float32` | `float32` | `float64` | `complex` |
| `float64` | `float64` | `float64` | `float64` | `float64` | `float64` | `float64` | `float64` | `complex` |
| `complex` | `complex` | `complex` | `complex` | `complex` | `complex` | `complex` | `complex` | `complex` |

## 5.2. Неявное продвижение

Неявное продвижение выполняется автоматически при смешанных числовых операциях по правилам §5.1.

## 5.3. Явное приведение

Для явного изменения числового типа используется:

```lacs
cast(value, Type)
```

Пример:

```lacs
float32 x = cast(y, float32)
```

Если преобразование может привести к потере точности или диапазона, это не является автоматической ошибкой: результат определяется целевым типом. Компилятор вправе выдать предупреждение.

Преобразования `complex` в обычные числовые типы не выполняются автоматически и не определены базовым `cast`; для этого используются специальные операции над действительной и мнимой частями.

Приведение `bool`, `text` и контейнеров к числовым типам автоматически не выполняется.

# 7. Переменные

## 7.1. Явно типизированные переменные

В ядре LACS объявление переменной имеет форму:

```text
Type name = expression
```

Примеры:

```lacs
int x = 5
float y = 3.14
text name = "Alex"
```

После объявления тип переменной не изменяется.

```lacs
int x = 5
x = 7          # OK
x = "hello"   # ошибка компиляции
```

Автоматический синтаксис вида `x := 5` в ядре отсутствует.

# 8. Динамический тип `let`

`let` не входит в ядро языка.

Он предоставляется встроенной стандартной библиотекой:

```lacs
import std.let
```

После импорта `let` является типом библиотеки и может использоваться в обычных типовых объявлениях.

```lacs
let x = 5
x = 3.14
x = "hello"
x = None
```

Семантика `let`:

- текущее значение хранится вместе с текущим runtime-типом;
- новое присваивание может менять runtime-тип;
- операции, невозможные для текущего runtime-типа, приводят к ошибке выполнения;
- компилятор может диагностировать очевидно невозможные операции, если это доказуемо статически;
- `let` может содержать `None`;
- `let` предназначен только для случаев, когда динамика нужна осознанно.

Динамика `let` не распространяется на остальные типы LACS.

Пример смешанного списка:

```lacs
let list values = [1, "two", 3.0]
```

# 9. Константы

Синтаксис:

```lacs
const Type NAME = expression
```

Примеры:

```lacs
const int N = 1024
const float PI = 3.141592653589793
const text TITLE = "LACS"
```

Инициализатор `const` должен быть вычислим на этапе компиляции.

`const` запрещает переназначение binding.

Для mutable-значения это не запрещает изменение самого объекта:

```lacs
const int list values = [1, 2]
values.append(3)   # допустимо
values = [4, 5]    # ошибка
```

# 10. Категории типов: value и reference

Для семантики присваивания и владения LACS различает **value-типы** и **reference-типы**.

## 10.1. Value-типы

К value-типам относятся:

```text
int8
int16
int32
int64
float16
float32
float64
bool
complex
text
struct
enum
tuple
fset
array
```

При обычном присваивании создаётся независимое значение.

## 10.2. Reference-типы

К reference-типам относятся:

```text
list
set
dict
```

Они представляют изменяемые объекты, существующие независимо от конкретного binding.

Обычное присваивание reference-типа в LACS всё равно имеет **семантику копии**. Для получения явной ссылки используется `.link()` (§24).

Таким образом, reference-тип говорит о природе объекта и его модели памяти, а не означает автоматическое aliasing при любом присваивании.

## 11.1. Общая таблица

| Конструкция | Свойства |

| `list<T>` | изменяемая последовательность одного типа |

# 12. Статические массивы

## 12.1. Тип

Статический массив имеет форму:

```text
T[N]
```

Например:

```lacs
int[10] buf
float[256] values
```

`N` — положительная целочисленная константа, известная на этапе компиляции.

Размер является частью типа:

```text
int[10]
```

и

```text
int[20]
```

являются разными типами.

## 12.2. Инициализация

Массив без явного инициализатора заполняется нулевым значением типа элемента, если для типа элемента определено нулевое значение.

Для фундаментальных типов нулевые значения следующие:

```text
целые       -> 0
floating    -> +0.0
bool        -> false
complex     -> 0 + 0i
text        -> ""
```

Для пользовательских и составных типов нулевое значение должно быть однозначно выводимо из их полей/элементов. Если оно не определено, явный инициализатор массива обязателен.

Пример:

```lacs
int[3] a
```

логически содержит:

```text
[0, 0, 0]
```

Явная инициализация:

```lacs
int[3] a = [1, 2, 3]
```

Количество элементов при явной инициализации должно точно соответствовать размеру массива.

## 12.3. Семантика

Массив является value-типом.

```lacs
int[3] a = [1, 2, 3]
int[3] b = a
```

`b` является независимой копией `a`.

# 13. List

`list<T>` — изменяемая упорядоченная последовательность элементов одного типа.

Вызовы вроде `list.append(x)` и `dict.keys()` являются встроенными операциями соответствующих типов; пользовательская система методов в текущем ядре отсутствует.

Пример:

```lacs
int list nums = [1, 2, 3]
text list labels = ["a", "b"]
```

Операции:

```lacs
nums[i]
nums[i] = 10
nums.append(10)
nums.insert(10, i)
nums.remove(i)
nums.pop()
nums.clear()
```

Вызовы вроде `append`, `insert`, `remove`, `pop`, `clear`, `keys` и `values` являются встроенными операциями соответствующих стандартных типов. Они не означают наличие общей пользовательской системы методов в ядре языка.

Свойство:

```text
.len
```

`pop()` на пустом списке — ошибка выполнения.

Индексирование поддерживает отрицательные индексы (§22).

Обычное присваивание списка создаёт независимую копию (§24).

---

# 14. Tuple

`tuple<T>` — неизменяемая упорядоченная последовательность одного типа.

Пример:

```lacs
text tuple states = ["SCAN", "PEAK", "LOCK"]
```

Разрешено чтение:

```lacs
states[0]
```

Запись запрещена.

`.len` возвращает количество элементов.

Tuple является value-типом.

Литерал tuple определяется по ожидаемому типу, если синтаксис литерала неоднозначен.

---

# 15. Set и fset

`set<T>` хранит уникальные элементы. Порядок элементов не гарантируется.

Пример:

```lacs
int set ids = (1, 2, 2, 3)
```

Логическое содержимое:

```text
{1, 2, 3}
```

Поддерживаются:

```lacs
ids.add(4)
ids.remove(4)
ids.clear()
4 in ids
```

`.len` возвращает количество элементов.

`fset<T>` имеет ту же модель уникальных элементов, но не поддерживает изменение после создания.

При отсутствии достаточного контекста для выбора между tuple/set/fset компилятор обязан выдать ошибку неоднозначности.

---

# 16. Dict

Словарь имеет тип:

```text
dict<K, V>
```

или сокращённую форму:

```text
K:V dict
```

Пример:

```lacs
text:int dict ages = {
    "alice": 25,
    "bob": 30
}
```

Операции:

```lacs
ages["alice"]
ages["alice"] = 26
"alice" in ages
ages.len
ages.keys()
ages.values()
```

Чтение отсутствующего ключа является ошибкой выполнения.

При совпадении ключей в литерале используется последнее значение.

Ключом может быть только hashable-тип (§17).

---

# 17. Hashability и равенство

Hashable-значение должно иметь стабильное равенство и hash во время использования в `set` или как ключ `dict`.

В MVP hashable являются:

```text
int8, int16, int32, int64
float16, float32, float64
bool
text
complex
None
enum
```

`tuple` и `fset` hashable, если каждый их элемент hashable.

Не являются hashable:

```text
array
list
set
dict
```

Для контейнеров `==` по умолчанию является структурным сравнением соответствующих элементов.

Для `struct` автоматическое структурное `==` в текущей версии не вводится: равенство пользовательских структур остаётся отдельным вопросом generic/operator system.

Для reference-значений `is` проверяет идентичность объекта, а `==` — содержимое.

# 18. Операторы и приоритет

Приоритет от высокого к низкому:

| Уровень | Операторы | Назначение |
|---:|---|---|
| 1 | `a[b]`, `f(...)` | индексирование, срез, вызов |
| 2 | `+x`, `-x`, `!x` | унарные операции |
| 3 | `*`, `/`, `//`, `%` | арифметика |
| 4 | `+`, `-` | сложение и вычитание |
| 5 | `<`, `>`, `<=`, `>=`, `in` | порядок и принадлежность |
| 6 | `==`, `!=`, `is`, `is not` | равенство и identity |
| 7 | `&&` | логическое И |
| 8 | `||` | логическое ИЛИ |
| 9 | `if ... | elif ... | else ...` | тернарное выражение |

Все бинарные операторы левоассоциативны, если специально не указано иное.

## 18.1. Arithmetic

Поддерживаются:

```text
+
-
*
/
//
%
```

`/` для двух целочисленных операндов всегда возвращает `float` (`float64`), независимо от разрядности целых операндов.

Если хотя бы один операнд `/` является floating-point или `complex`, сначала применяется числовое продвижение §5.1, после чего выполняется обычное деление полученного числового типа.

`//` выполняет целочисленное деление с округлением вниз и в текущей версии применяется только к целочисленным операндам.

`%` в текущей версии применяется только к целочисленным операндам и использует ту же пару `//`/`%`, что и определение ниже.

Для целых выполняется:

```text
a == (a // b) * b + (a % b)
```

Деление на ноль — ошибка выполнения.

## 18.2. Text

Поддерживаются:

```lacs
"hello" + " world"
"ab" * 3
```

`text + text -> text`.

`text * int -> text`.

Отрицательный множитель даёт пустую строку.

## 18.3. Logical operators

`&&` и `||` работают только с `bool`.

Используется короткое замыкание:

```lacs
a && b
c || d
```

Правая часть `&&` не вычисляется при `a == false`.

Правая часть `||` не вычисляется при `c == true`.

Автоматического преобразования числа, строки или контейнера в `bool` нет.

## 18.4. Equality

`==` и `!=` сравнивают значения.

Операнды должны быть совместимы для сравнения.

## 18.5. Identity

`is` и `is not` проверяют identity для reference-значений и `None`.

Пример:

```lacs
int list a = [1, 2]
int list b = a.link()
int list c = [1, 2]

a == b   # true
a == c   # true

a is b   # true
a is c   # false
```

Для обычных value-типов `is` и `is not` запрещены.

# 19. Составные присваивания

Поддерживаются:

```text
+=
-=
*=
/=
//=
```

Например:

```lacs
x += y
```

семантически эквивалентно:

```lacs
x = x + y
```

с учётом типовой системы.

Для явно типизированной переменной результат должен быть совместим с объявленным типом.

Например:

```lacs
int x = 5
x /= 2
```

является ошибкой компиляции, поскольку `/` для двух целых даёт floating-point результат.

---

# 20. Инкремент и декремент

Поддерживаются:

```text
i++
++i
i--
--i
```

Операторы применимы только к целочисленным lvalue.

Префиксная форма изменяет значение и возвращает новое значение.

Постфиксная форма изменяет значение и возвращает старое значение.

Пример:

```lacs
int x = 5
int a = x++   # a = 5, x = 6
int b = ++x   # x = 7, b = 7
```

Переполнение при `++`/`--` — ошибка выполнения.

---

# 21. Множественное присваивание

Синтаксис:

```lacs
a, b, c = expr1, expr2, expr3
```

Семантика двухфазная:

1. все выражения справа вычисляются слева направо;
2. после этого результаты присваиваются слева направо.

Количество lvalue и выражений должно совпадать.

Пример:

```lacs
arr[i], arr[j] = arr[j], arr[i]
```

Множественное присваивание не является распаковкой контейнера переменной длины.

Конструкция:

```lacs
a, b = some_list
```

запрещена.

---

# 22. Индексация и срезы

## 22.1. Индексация

Индексирование последовательностей:

```lacs
value[index]
```

поддерживается для:

- массивов;
- `list`;
- `tuple`;
- `text`.

Для `dict` синтаксис `value[key]` означает поиск по ключу.

Индексы могут быть отрицательными.

```lacs
a[-1]
a[-2]
```

означают последний и предпоследний элемент соответственно.

После нормализации отрицательный индекс обязан попадать в диапазон:

```text
0 <= index < len
```

Иначе возникает ошибка выполнения.

## 22.2. Срезы

Синтаксис:

```text
[start:end:step]
```

вдохновлён Python, но в LACS срезы являются **строгими**.

Примеры:

```lacs
a[2:8]
a[2:]
a[:8]
a[:]
a[::2]
a[10:0:-1]
```

Пропущенные части означают границу по умолчанию:

```text
start отсутствует → начало
end отсутствует   → конец
step отсутствует  → 1
```

### `step`

Шаг не может быть равен `0`.

Отрицательный шаг разрешён.

### Строгие границы

В отличие от Python, выход границы среза за длину последовательности является ошибкой выполнения.

Например, для последовательности длины `10`:

```lacs
a[2:8]    # OK
a[2:10]   # OK
a[2:11]   # ошибка
a[-1:5]   # проверяется после нормализации индексов
```

Для среза после нормализации должны выполняться все соответствующие ограничения границ.

Индексы `start` и `end` поддерживают отрицательные значения.

### Результат среза

Срез создаёт **новое значение**, а не view исходной последовательности.

- `list` → новый `list`;
- `tuple` → новый `tuple`;
- `array` → новая последовательность элементов соответствующего типа; если длина не является частью известного на compile-time типа, результатом является `list`;
- `text` → новый `text`.

Оптимизация копирования допустима, пока наблюдаемое поведение остаётся эквивалентным.

---

# 23. Тернарное выражение

Синтаксис:

```lacs
text status = if ready "OK" | else "WAIT"
```

и:

```lacs
text sign = if x > 0 "+" | elif x < 0 "-" | else "0"
```

`if` обязателен.

`elif` может повторяться.

`else` обязателен.

Все ветви являются выражениями.

Если все ветви имеют один тип, результат имеет этот тип.

Если типы различаются, они должны иметь совместимый общий тип по правилам типовой системы. Иначе — ошибка компиляции.

# 24. Управляющие конструкции

## 24.1. if

```lacs
if cond {
    ...
} elif cond2 {
    ...
} else {
    ...
}
```

Условие обязано иметь тип `bool`.

## 24.2. loop

```lacs
loop {
    if done {
        break
    }
}
```

`loop` выполняется бесконечно, пока не произойдёт `break`, завершение функции или ошибка.

## 24.3. while

```lacs
while cond {
    ...
}
```

Условие должно иметь тип `bool`.

## 24.4. Классический for

```lacs
for int i = 0; i < N; i++ {
    ...
}
```

Порядок:

```text
initialization → condition → body → step → condition
```

Переменная цикла имеет область видимости всего `for`.

## 24.5. Диапазонный for

```lacs
for i in 0 -> N {
    ...
}
```

даёт:

```text
0, 1, ..., N-1
```

С шагом:

```lacs
for i in 0 -> N; 2 {
    ...
}
```

Шаг не может быть равен `0`.

Отрицательный шаг:

```lacs
for i in 10 -> 0; -2 {
    ...
}
```

Верхняя граница является исключающей.

## 24.6. Перебор контейнеров

```lacs
for x in list {
    ...
}
```

Для `dict`:

```lacs
for k, v in dict {
    ...
}
```

Для `list`, `tuple`, массивов и `text` используется логический порядок от начала к концу.

Порядок `set`, `fset` и `dict` не гарантируется.

## 24.7. break и continue

`break` завершает ближайший цикл.

`continue` переходит к следующей итерации ближайшего цикла.

Использование вне цикла — ошибка компиляции.

# 25. Функции

## 25.1. Объявление

```lacs
fn add(int a, int b) -> int {
    return a + b
}
```

Возвращаемый тип может быть опущен:

```lacs
fn add(int a, int b) {
    return a + b
}
```

В этом случае компилятор выводит его по `return`.

## 25.2. return

```lacs
return expr
```

возвращает значение.

```lacs
return
```

возвращает `None`.

Отсутствие `return expr` эквивалентно возвращению `None`.

Если разные пути функции возвращают несовместимые типы и невозможно определить общий тип, возникает ошибка компиляции.

## 25.3. Перегрузка и default arguments

В ядре LACS MVP:

- перегрузка функций не поддерживается;
- значения параметров по умолчанию не поддерживаются.

---

# 26. Тип функции

Функции являются значениями первого класса.

Тип функции записывается:

```text
fn(T1, T2, ...) -> R
```

Пример:

```text
fn(int, int) -> int
```

означает функцию с двумя аргументами `int` и результатом `int`.

Тип функции может использоваться в объявлении переменной:

```lacs
fn(int) -> int f = x => x * 2
```

Функциональные значения можно:

- сохранять в переменных;
- передавать как аргументы;
- возвращать из функций;
- использовать в generic-функциях.

---

# 27. Generics

LACS поддерживает статические generic-типы и generic-функции.

Параметр типа обозначается заглавной латинской буквой или именем типа-параметра:

```text
T
R
K
V
```

## 27.1. Generic-функция

```lacs
fn identity<T>(T x) -> T {
    return x
}
```

Вызов:

```lacs
int x = identity(10)
text y = identity("hello")
```

Компилятор выводит `T` из аргумента и контекста.

При необходимости тип может быть указан явно:

```lacs
int x = identity<int>(10)
```

## 27.2. Generic-контейнеры

Каноническая форма типов:

```text
list<T>
set<T>
fset<T>
dict<K, V>
tuple<T>
```

Поддерживаются удобные сокращения:

```text
T list
T set
T fset
K:V dict
T tuple
```

## 27.3. Generic `map`

Концептуальная сигнатура:

```text
map<T, R>(list<T>, fn(T) -> R) -> list<R>
```

## 27.4. Generic constraints

Generics могут иметь ограничения:

```lacs
fn max<T: Comparable>(T a, T b) -> T {
    if a > b {
        return a
    }
    return b
}
```

Минимальные встроенные constraints:

```text
Equatable
Comparable
Hashable
```

`Equatable` требует корректного `==`/`!=`.

`Comparable` требует операций порядка.

`Hashable` требует hash и совместимого равенства.

Пользовательские traits/interfaces для создания собственных constraints в этой версии не вводятся.

## 27.5. Generic-типы

Пользовательские `struct` могут иметь параметры типа:

```lacs
struct Pair<T, R> {
    T first
    R second
}

Pair<int, text> value = Pair<int, text>(10, "hello")
```

Параметры типа структуры подставляются на этапе компиляции.

## 27.6. Generics и compile-time

Generic-код является статическим.

Типовые параметры не требуют runtime type dispatch, если конкретная реализация может быть определена компилятором.

Механизм генерации специализированного кода является деталью компилятора.

---

# 28. Лямбды и замыкания

Лямбда без блока:

```lacs
fn(int) -> int f = x => x * 2
```

Несколько параметров:

```lacs
fn(int, int) -> int g = (a, b) => a + b
```

Блочная lambda:

```lacs
fn(int, int) -> int max2 = (a, b) => {
    if a > b {
        return a
    } else {
        return b
    }
}
```

Типы параметров и результата выводятся из контекста.

Если контекст недостаточен для однозначного вывода, компилятор выдаёт ошибку.

## 28.1. Захват переменных

Lambda захватывает внешний binding, а не снимок значения.

```lacs
int x = 10
fn(int) -> int f = () => x
x = 20
```

Вызов `f()` возвращает `20`.

Если closure переживает исходную область видимости, необходимые захваченные binding'и должны сохраняться столько, сколько необходимо существующей closure.

Конкретный механизм хранения closure — деталь реализации.

# 29. Стандартные функции высшего порядка

В `std.collections` доступны:

```text
map
filter
reduce
for_each
find
any
all
```

Их generic-семантика определяется системой generics.

## 29.1. Семантика

`map` создаёт новый контейнер с преобразованными элементами.

`filter` оставляет элементы, для которых predicate возвращает `true`.

`reduce` сворачивает элементы слева направо.

`for_each` выполняет callback ради побочного эффекта.

`find` возвращает первый подходящий элемент или `None`.

`any` возвращает `true`, если существует хотя бы один подходящий элемент.

`all` возвращает `true`, если все подходят; для пустой последовательности результат `true`.

# 30. Optional-значения

Для представления «значение типа `T` или отсутствие значения» используется:

```text
T?
```

Например:

```lacs
fn find_user(text name) -> User? {
    ...
}
```

`T?` может содержать:

```text
T
```

или:

```text
None
```

Проверка:

```lacs
if user is None {
    ...
} else {
    ...
}
```

После проверки компилятор выполняет локальное сужение типа в соответствующей области.

Операции, требующие `T`, нельзя применять к `T?` без проверки на `None`.

`find` имеет результат `T?`.

# 31. Область видимости

LACS имеет:

- область модуля;
- область функции;
- блоковую область `{ ... }`;
- область цикла.

Каждый `if`, `for`, `while` и явно записанный блок создаёт вложенную область.

Допускается shadowing:

```lacs
int x = 10

if true {
    text x = "hello"
    println(x)
}

println(x)
```

Внутреннее имя скрывает внешнее только внутри своей области.

Повторное объявление имени в одной и той же области запрещено.

# 32. Struct

`struct` создаёт пользовательский статический value-тип.

Пример:

```lacs
struct User {
    text name
    int age
}
```

Создание:

```lacs
User u = User("Alex", 20)
```

Для каждого `struct` автоматически существует конструктор со всеми полями в порядке их объявления.

Доступ:

```lacs
u.name
u.age
```

Поля по умолчанию изменяемы, если binding не является `const`.

`struct` является value-типом.

Присваивание структуры создаёт независимую логическую копию.

Пользовательские методы и наследование не являются частью текущего ядра.

---

# 33. Enum

`enum` задаёт конечное множество именованных значений.

Пример:

```lacs
enum Mode {
    SCAN,
    PEAK,
    LOCK
}
```

Использование:

```lacs
Mode mode = Mode.SCAN
```

Enum-значения сравниваются через `==` и `!=`.

Enum не является `text` и не преобразуется в `text` автоматически.

Конкретное внутреннее представление enum является деталью реализации.

---

# 34. Match

`match` является конструкцией ядра языка и обеспечивает pattern matching с compile-time проверкой.

Пример:

```lacs
match mode {
    Mode.SCAN => println("scan")
    Mode.PEAK => println("peak")
    Mode.LOCK => println("lock")
}
```

Wildcard:

```lacs
match mode {
    Mode.SCAN => println("scan")
    _ => println("other")
}
```

Компилятор проверяет полноту обработки вариантов enum, если отсутствует `_`.

Для неполного `match` возникает ошибка компиляции.

На текущем этапе поддерживаются простые значения, enum-паттерны, литералы и `_`. Более сложные destructuring-паттерны могут быть добавлены позже.

---

# 35. Порядок вычисления

LACS использует строго определённый порядок вычисления: **слева направо**.

Для:

```lacs
f(a(), b(), c())
```

сначала выполняется `a()`, затем `b()`, затем `c()`, после чего вызывается `f`.

Для бинарных операций сначала вычисляется левый операнд, затем правый.

Исключение составляют `&&` и `||`, где действует short-circuit.

Для индексирования сначала вычисляется контейнер, затем индекс.

Для множественного присваивания используется отдельное двухфазное правило §21.

# 36. Присваивание, копирование и ownership

LACS использует явную модель копирования и владения.

## 36.1. Обычное присваивание

Обычное присваивание имеет семантику копии.

```lacs
int list a = [1, 2, 3]
int list b = a

b.append(4)
```

После этого:

```text
a == [1, 2, 3]
b == [1, 2, 3, 4]
```

Для mutable-контейнеров копия является глубокой на семантическом уровне.

Реализация может применять copy-on-write, move elision и другие оптимизации, если наблюдаемое поведение сохраняется.

## 36.2. Параметры функций

Value-типы передаются по значению.

Mutable reference-контейнеры без модификатора `copy` передаются как borrow/alias исходного объекта:

```lacs
fn sort(int list data) {
    ...
}
```

Изменения `data` изменяют объект вызывающей стороны.

Параметр с `copy`:

```lacs
fn modify(copy int list data) {
    ...
}
```

получает независимую копию.

Компилятор обязан проверять отсутствие конфликтующего одновременного mutable-доступа в соответствии с правилами borrowing.

## 36.3. Явная ссылка `.link()`

Для явного получения borrowed-ссылки на доступное изменяемое значение или объект используется `.link()`:

```lacs
int list a = [1, 2, 3]
int list b = a.link()
```

`b` и `a` обозначают один объект.

```lacs
b.append(4)
```

изменяет объект, видимый через `a`.

`.link()` не передаёт владение объектом.

Срок жизни link не может превышать срок жизни соответствующего владельца. Компилятор обязан отклонять код, в котором borrow может пережить владельца. Поэтому к моменту уничтожения владельца ни один связанный live-borrow не должен существовать. На уровне наблюдаемой семантики связанный binding заканчивает существование вместе с допустимым временем жизни владельца.

Обычное присваивание от borrowed binding выполняет обычную семантику копирования и не переносит borrow автоматически. Для получения ещё одной ссылки необходимо явно вызвать `.link()` на доступном binding'е.

## 36.4. Borrowing model

В основу borrowing положено правило эксклюзивного доступа:

- одновременно допускается не более одного активного mutable borrow одного объекта;
- при активном mutable borrow другие конфликтующие borrow не допускаются;
- пользовательский синтаксис отдельных read-only borrow пока не вводится и может быть добавлен позже.

`.link()` в текущей версии создаёт явный borrowed binding с доступом к тому же объекту. Дополнительные квалификаторы для различения shared/read-only и mutable borrow остаются отдельным вопросом.

## 36.5. Возврат

Возвращаемое значение имеет семантику копии.

Компилятор может устранить физическую копию при сохранении наблюдаемой семантики.

Возврат ссылки, срок жизни которой зависит от локального владельца, запрещён.

# 37. Изменяемость

Изменяемые категории:

```text
array
list
set
dict
```

`struct`-значение может быть изменено через его поля, если соответствующий binding не является `const`.

Неизменяемые категории:

```text
text
tuple
fset
enum
scalar value types
```

`const` запрещает изменение binding, но не обязательно внутреннюю мутабельность объекта, на который он указывает, согласно правилам §9.

# 38. Инициализация и время жизни

Локальная переменная начинает существовать после успешного завершения её инициализатора.

Глобальные переменные инициализируются до вызова `main`.

Порядок межмодульной глобальной инициализации определяется графом зависимостей импортов.

Циклическая зависимость глобальной инициализации является ошибкой компиляции.

Время жизни локального значения заканчивается после того, как:

- binding больше не существует;
- значение не удерживается допустимым closure/borrow;
- отсутствует другой разрешённый владелец.

Конкретный механизм управления памятью может быть:

- reference counting;
- tracing GC;
- ownership-based reclamation;
- гибридная модель.

Это деталь реализации, если наблюдаемая семантика владения и borrowing остаётся неизменной.

# 39. Строки

`text` — неизменяемая последовательность Unicode scalar values.

На уровне внешнего представления строк используется Unicode; внутренняя кодировка реализации рекомендуется UTF-8.

## 39.1. Длина

```lacs
text s = "hello"
s.len()
```

возвращает количество Unicode scalar values, хранящихся в строке, а не количество UTF-8 байт.

## 39.2. Индексация

```lacs
text s = "hello"
text c = s[0]
```

возвращает `text` длины один Unicode scalar value.

Поддерживаются отрицательные индексы.

## 39.3. Срезы

```lacs
text s = "hello"
text a = s[1:4]
```

Результатом является новый `text`.

Срезы следуют строгим правилам §22.

# 40. Модули и import

Каждый `.lac` файл является модулем.

Импорт:

```lacs
import std.math
```

после чего обращения к экспортированным именам выполняются через пространство имён модуля:

```lacs
std.math.sqrt(25.0)
```

Допустима выборка отдельных экспортов:

```lacs
from std.math import sqrt, sin
```

После этого:

```lacs
sqrt(25.0)
```

Допустим псевдоним:

```lacs
import std.math as math
```

и:

```lacs
math.sqrt(25.0)
```

Модуль загружается один раз в пределах запуска программы.

Циклические импорты в MVP запрещены.

# 41. Экспорт символов

Объявление верхнего уровня, предназначенное для использования из других модулей, помечается `export`:

```lacs
export const float PI = 3.141592653589793

export fn square(float x) -> float {
    return x * x
```

Неэкспортированные символы доступны только внутри модуля.

Не рекомендуется экспортировать глобальные mutable-переменные, но язык это не запрещает.

# 42. Стандартная библиотека

Стандартная библиотека поставляется вместе с LACS и является частью стандартной поставки, но не частью синтаксического ядра.

Минимальная структура:

```text
std.let
std.io
std.math
std.collections
```

Дополнительные специализированные библиотеки могут добавляться позднее.

## 42.1. Prelude

В LACS существует автоматически подключаемый `prelude`.

Он содержит минимальные общеупотребительные средства, в частности:

```lacs
println(value)
```

Поэтому обычный вывод не требует явного `import`.

Функции и символы, не входящие в prelude, подключаются через `import`.

Функции `print()` в LACS нет.

Дополнительные параметры `println`, включая изменение завершающего символа, в текущей версии не входят в ядро/стандартную поставку и могут быть добавлены позднее.

## 42.2. `std.let`

Содержит динамический тип `let`.

```lacs
import std.let
```

`let` не резервируется грамматикой ядра и не существует без импорта соответствующей библиотеки.

## 42.3. `std.io`

Общие операции ввода-вывода:

```text
read_file
write_file
read_lines
```

Примеры:

```lacs
text content = std.io.read_file("data.txt")
std.io.write_file("out.txt", content)
text list lines = std.io.read_lines("data.txt")
```

## 42.4. `std.math`

Стандартная математическая библиотека содержит как минимум:

```text
sqrt
abs
sin
cos
tan
asin
acos
atan
atan2
exp
log
log10
pow
floor
ceil
round
min
max
```

Математические константы также находятся здесь:

```text
pi
e
phi
tau
```

Они больше не являются обязательными глобальными именами ядра.

## 42.5. `std.collections`

Содержит generic-функции высшего порядка:

```text
map
filter
reduce
for_each
find
any
all
```

# 43. Обработка ошибок

## 43.1. Compile-time errors

Минимальный набор:

- неизвестный идентификатор;
- неизвестная функция;
- неизвестный тип;
- неизвестный модуль;
- неизвестный экспортируемый символ;
- изменение `const` binding;
- несовместимость типов;
- неправильное использование optional (`T?`);
- неоднозначный вывод типа;
- неоднозначный контейнерный литерал;
- неправильный синтаксис;
- `break`/`continue` вне цикла;
- `return` вне функции;
- несовпадение количества значений в множественном присваивании;
- использование `is` для несовместимых value-типов;
- нарушение правил `struct`/`enum`;
- циклический импорт;
- отсутствие `main()`;
- несколько `main()`;
- несовместимый возвращаемый тип;
- нарушение generic constraints;
- попытка вернуть borrow, переживающий владельца.

## 43.2. Runtime errors

Минимальный набор:

- деление на ноль;
- переполнение целого типа;
- выход индекса за границы;
- выход строгого среза за допустимые границы;
- отсутствующий ключ `dict`;
- удаление отсутствующего элемента `set`;
- `pop()` пустого `list`;
- недопустимая операция над `None`;
- недопустимая операция текущего runtime-типа `let`;
- несовместимое runtime-значение;
- нулевой шаг диапазона;
- ошибка FFI;
- ошибка стандартной библиотеки.

По умолчанию runtime error завершает текущий процесс.

---

# 44. Обработка ожидаемых ошибок

Ядро LACS не содержит обязательного `try/catch`.

Для ожидаемого отсутствия значения используется:

```text
T?
```

Для более богатых моделей ошибок позднее может появиться generic-тип:

```text
Result<T, E>
```

Он **не входит в текущую версию**.

Ожидаемая ошибка должна по возможности моделироваться возвращаемым значением или специальным типом стандартной библиотеки, а программная ошибка — runtime error.

---

# 45. FFI

LACS допускает объявления внешних функций:

```lacs
extern fn native_function(int x) -> int
```

FFI предназначен для:

- системных вызовов;
- библиотек C/C++;
- высокопроизводительных нативных библиотек;
- взаимодействия с ОС;
- доступа к аппаратным возможностям.

## 45.1. ABI

Точное ABI и представление памяти для FFI фиксируются ABI-документацией конкретного компилятора/target.

В безопасной части FFI должны быть доступны как минимум базовые scalar-типы и специально разрешённые структуры с известным layout.

Произвольные LACS-контейнеры не считаются автоматически совместимыми с C ABI.

Особенно:

```text
list
set
dict
```

не должны передаваться напрямую во внешний код без специального FFI-адаптера.

`text` также требует явного ABI-представления при передаче во внешний код.

---

# 46. Safe и unsafe

Основная часть LACS является safe by default.

Raw pointers не являются обычным пользовательским типом безопасного ядра.

Для операций, помеченных реализацией или библиотекой как небезопасные, предусматривается граница:

```lacs
unsafe {
    ...
}
```

В unsafe-контексте в будущих версиях могут предоставляться:

- raw pointers;
- ручная работа с памятью;
- низкоуровневые ABI-операции;
- другие операции, нарушающие гарантии safe core.

Текущая версия не вводит полноценную пользовательскую pointer-систему в обычном safe-коде.

# 47. Проекты и сборка

Компиляция одного файла допустима:

```text
lacs build main.lac
```

Для многомодульного проекта рекомендуется структура:

```text
project/
├── src/
│   ├── main.lac
│   ├── math.lac
│   └── user.lac
└── lacs.toml
```

`lacs.toml` описывает проект и параметры сборки.

Минимальный пример:

```toml
name = "my_project"
version = "0.1.0"
entry = "src/main.lac"
```

Сборка проекта:

```text
lacs build
```

Компилятор строит граф модулей по `import`, разрешает зависимости и создаёт единый executable.

Команда:

```text
lacs run
```

является инструментом командной строки и не является конструкцией языка; она может выполнить сборку и запуск результата.

Система внешних пакетов и пакетный менеджер не входят в текущую спецификацию.

# 48. LACS IR и компиляция

AST является представлением исходной структуры программы и не обязан совпадать с формой конечного кода.

Рекомендуется использовать отдельный LACS IR между semantic analysis и LLVM IR:

```text
AST
 ↓
semantic analysis
 ↓
LACS IR
 ↓
LLVM IR
```

LACS IR предназначен для:

- типов;
- контрольного потока;
- представления value/reference semantics;
- generic specialization;
- lowering высокоуровневых конструкций.

LLVM отвечает за target-specific оптимизацию и генерацию нативного кода.

---

# 49. Производительность и семантическая стоимость

Статически типизированные конструкции LACS не должны требовать динамического runtime dispatch только потому, что язык поддерживает динамический `let`.

В частности, использование:

```text
int
float
bool
array
struct
enum
```

не должно автоматически приводить к runtime-проверке их типов.

Динамический overhead допускается для возможностей, которые сами по себе используют runtime-семантику, например `let`.

Реализация может применять:

- inlining;
- constant folding;
- dead-code elimination;
- loop optimization;
- vectorization;
- copy elision;
- move elision;
- copy-on-write;
- другие оптимизации,

если наблюдаемая семантика языка сохраняется.

---

# 50. Что не входит в текущий Core

Следующие возможности сознательно отложены:

- `uint8`, `uint16`, `uint32`, `uint64` как фундаментальные типы;
- `float8`;
- будущий `uint` вне ядра;
- методы и полноценная объектная система;
- inheritance;
- пользовательские traits/interfaces;
- const generics;
- сложные pattern matching/destructuring;
- `Result<T, E>`;
- полноценная pointer-система safe core;
- ручное управление памятью в обычном safe-коде;
- дополнительные параметры `println`;
- пакетный менеджер;
- пользовательские конструкторы `struct`;
- перегрузка функций;
- default arguments.

---

# 51. Будущие библиотеки и расширения

Новые возможности должны по возможности добавляться как библиотеки, а не в core языка.

Принцип:

```text
Core
    ↓
только фундаментальные конструкции языка

Standard Library
    ↓
универсальные готовые возможности

Specialized Libraries
    ↓
математика, графика, численные вычисления,
сетевые возможности, ML и т. д.

unsafe / FFI
    ↓
низкоуровневый внешний мир
```

Это позволяет расширять экосистему LACS без постоянного усложнения фундаментальной модели языка.

# 52. Пример полной программы

```lacs
import std.collections

struct User {
    text name
    int age
}

enum Access {
    User,
    Admin
}

fn is_adult(User user) -> bool {
    return user.age >= 18
}

fn main() {
    User alice = User("Alice", 20)
    User bob = User("Bob", 15)

    User list users = [alice, bob]

    User list adults = std.collections.filter(
        users,
        user => is_adult(user)
    )

    for user in adults {
        println(user.name)
    }
}
```

# 53. Сводка фундаментальной модели

LACS в текущей версии придерживается следующих принципов:

```text
статическая типизация
        ↓
compile-time проверки
        ↓
LACS IR
        ↓
LLVM
        ↓
native code
```

Динамика является отдельной возможностью:

```text
std.let
    ↓
let
    ↓
runtime type
```

Контейнеры разделены по назначению:

```text
array  → фиксированный размер, value type
list   → динамический размер, mutable reference type
tuple  → immutable sequence
set    → mutable unique collection
fset   → immutable unique collection
dict   → mutable key/value collection
```

Память строится вокруг:

```text
copy
+
borrow/link
+
ownership
```

а низкоуровневый доступ изолируется:

```text
safe LACS
    ↓
unsafe / FFI
    ↓
native world
```
